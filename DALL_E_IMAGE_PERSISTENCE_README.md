# DALL-E Image Persistence Implementation

## Overview

This implementation fixes the issue of disappearing DALL-E images by converting temporary Azure Blob Storage URLs to permanent Supabase Storage URLs. The solution ensures that recipe images generated by DALL-E remain accessible indefinitely.

## Problem Description

Previously, DALL-E generated images were stored as temporary signed URLs from Azure Blob Storage (`oaidalleapiprodscus.blob.core.windows.net`) with expiry parameters (`se=`). These URLs would expire after a certain time, causing images to disappear from recipes.

## Solution

The implementation includes:

1. **Image Storage Service** (`services/imageStorageService.ts`)
2. **Modified Recipe Service** (`services/recipeService.ts`)
3. **Setup Scripts** (`scripts/setupStorage.ts`)
4. **Backfill Script** (`scripts/backfillDallEImages.ts`)
5. **Test Suite** (`scripts/testImagePersistence.ts`)

## How It Works

### For New Recipes

1. When a recipe is saved via `saveRecipe()`, the system checks if the image URL is a temporary DALL-E URL
2. If it is, the image is downloaded from the DALL-E URL
3. The image is uploaded to Supabase Storage in the `recipe-images` bucket
4. The recipe is saved with the permanent Supabase Storage URL
5. The `is_dalle_image` flag is set to `false` to indicate it's now permanently stored

### For Existing Recipes

1. Run the backfill script to process existing recipes with `is_dalle_image = true`
2. The script downloads images from temporary URLs (if not expired)
3. Uploads them to Supabase Storage
4. Updates database records with permanent URLs

## Setup Instructions

### 1. Ensure Supabase Storage is Configured

Run the setup script to create the required storage bucket:

```bash
npx ts-node scripts/setupStorage.ts
```

This will:
- Create a `recipe-images` bucket in Supabase Storage
- Set appropriate permissions for public read access
- Test storage access

### 2. Backfill Existing Images

Convert existing DALL-E images to permanent storage:

```bash
npx ts-node scripts/backfillDallEImages.ts
```

This will:
- Process recipes with `is_dalle_image = true`
- Download images from temporary URLs
- Upload to Supabase Storage
- Update database records

### 3. Test the Implementation

Verify everything is working correctly:

```bash
npx ts-node scripts/testImagePersistence.ts
```

This will run a comprehensive test suite covering:
- URL detection logic
- Storage setup verification
- Image persistence functionality
- System diagnostics

## Technical Details

### Image Storage Path Structure

Images are stored in Supabase Storage with the following path structure:
```
recipe-images/
└── recipes/
    └── {userId}/
        └── {recipeId}_{timestamp}.{extension}
```

### URL Detection

The system identifies DALL-E URLs by checking for:
- Domain: `oaidalleapiprodscus.blob.core.windows.net`
- Expiry parameter: `se=`
- Signature parameter: `sig=`

### Error Handling

- If image download fails, the original URL is kept as fallback
- If upload to Supabase fails, the original URL is preserved
- Batch processing includes delays to avoid API rate limits
- Comprehensive logging for debugging

### Database Schema

The existing database schema is used without modifications:
- `recipes.image`: Stores the image URL (now permanent)
- `recipes.is_dalle_image`: Boolean flag (set to false after persistence)

## Environment Variables Required

Ensure these environment variables are set in your `.env` file:

```env
SUPABASE_URL=your_supabase_url
SUPABASE_PUBLIC_KEY=your_supabase_anon_key
OPENAI_DALL_E_API_KEY=your_openai_dalle_api_key
```

## Supabase Storage Policies

The following RLS policies should be set up in your Supabase dashboard for the `recipe-images` bucket:

1. **Upload Policy**: Allow authenticated users to upload to their own folder
   ```sql
   auth.uid()::text = (storage.foldername(name))[1]
   ```

2. **Read Policy**: Allow public read access
   ```sql
   true
   ```

3. **Delete Policy**: Allow users to delete their own images
   ```sql
   auth.uid()::text = (storage.foldername(name))[1]
   ```

## Troubleshooting

### Common Issues

1. **Storage bucket doesn't exist**
   - Run `npx ts-node scripts/setupStorage.ts`

2. **Permission denied errors**
   - Check Supabase RLS policies
   - Verify environment variables

3. **Images already expired**
   - Expired DALL-E URLs cannot be downloaded
   - These will be logged and skipped during backfill

4. **Network timeouts**
   - Reduce batch size in backfill script
   - Check internet connection

### Debug Mode

Enable detailed logging by checking the console output from the scripts. All operations are logged with appropriate prefixes for easy debugging.
